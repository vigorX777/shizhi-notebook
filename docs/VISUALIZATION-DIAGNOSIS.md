## 原因与证据边界

1. 生成决策：旧模板“必要时可视化”允许纯文字／选项表结束；未把空间、光照等明确作为默认图解场景。本次没有生成图，不是网页丢失生成后的图。
2. 展示协议：旧模板强调 learning-html 围栏／文件链接，缺少原生 visualize 内容引用。网页能够显示这种图解代码，不意味着聊天也会把代码块变为交互卡片。
3. 离线依赖：原生片段使用宿主主题变量／控件样式，裸片段搬到笔记页可能不完整；需要同一片段的独立导出，不可保存临时预览链接。

本机当前环境提供 visualize skill 1.0.49，其合同指定写 HTML fragment 并在最终回答输出原生 visualize 内容引用。官方文档 https://learn.chatgpt.com/docs/visualizations 说明可视化可用于参数／时空变化，部分平台及账号处于滚动开放，CLI／IDE 不支持此渲染。官方页面没有明确保证用户每个 Codex 桌面会话的可用性；因此只确认本机存在当前技能和协议，不把它推断成所有客户端均已支持。聊天实际展示以本次交付的原生示例和随后学习会话现场为准。

## 本次修改

- 导师模板：几何／空间、光照、运动等默认生成真实图；变化参数、视角、步骤帮助理解时生成交互；读取可用 visualize skill，最终题目小节用原生内容引用，不用代码块替代展示。没有能力时给明确的网页预览方式，不能声称已原生展示。
- learning/scripts/export-visual.mjs 与 assets/visualize.css：同一片段导出为离线 HTML，内嵌配套主题／控件样式，禁止网络资源；不会覆盖原片段。宿主专用能力不作为核心交互依赖。
- visualizations 接受原生片段 path 与独立副本 offlinePath；服务保存完整离线内容，按原生内容引用替换到对应笔记。缺失原生图解持有显示未完成，Stop 仍最多一次请求补整理。
- 原始 Source.answer 保留原生响应文本；笔记显示对应离线图解，不修改用户讲解历史或把新测试图写入正式题目。
