# 可重复验收

先运行 `npm test` 与 `npm run build`。自动化测试使用临时数据库，不能作为桌面自动归档成功的证据。

## 第一关：专用项目与真实桌面归档

1. 启动本机服务；在 Codex 桌面添加 learning 目录为学习项目，审核并信任配置和 hooks。新建会话，确认 MCP 工具可用。
2. 文字提问：「解方程 2x+3=7，请讲解步骤。」完成后，在网页确认一条数学笔记，题目与讲解可读，状态为已完整归档。
3. 原会话追问：「为什么移项要变号？」确认追加到原笔记，笔记数量不增加。问另一题或英语知识点，确认另建笔记。「谢谢」不增加笔记。
4. **真实拖入图片**：从 Finder 拖入 tests/fixtures/math-single.png，输入「讲解这道题」。确认网页有完整原图（1200×600）与讲解；原图下载 SHA-256 必须与文件一致。记录会话、轮次、笔记及附件 ID。
5. **真实粘贴截图**：使用 macOS 截图到剪贴板并 Cmd+V 粘贴到 Codex，提问。确认独立原图、题目和讲解。截图不能用 localImage API 合成输入替代。
6. **真实多图**：同一轮拖入 math-single.png 和 english-single.png，问「分别讲解」。确认分别保存不同科目笔记，来源同一轮次，每条引用对应原图。再拖入 math-multiple.png，确认同图两题拆为两笔记、共用原图、记录题号。
7. 执行 `npm run verify:live`，保存 .local/live-report.json。逐一核对步骤 2～6 的来源 ID、完整状态和附件摘要。只有来源对应真实操作，报告才算桌面证据。

如果返回 fileId、不可读取临时路径或远程链接，记录正式接口原始字段（不得公开敏感内容）；继续解决原图读取连接。**不得以手动补存代替本次要求。**

## 第二关：恢复与复习

| 操作 | 预期 |
|---|---|
| 重放同一事件 | 来源及笔记不重复 |
| 中断讲解 | 原题和已收集图片保留，状态未完成 |
| 暂停服务后真实提问，再重启 | 队列补处理；hook 已复制的原图仍在；遗漏整理清楚可见 |
| 搜索标题、讲解、知识点、心得 | 找到对应笔记，筛选结果保持稳定 |
| 修改标题、科目、标签、心得、错因和掌握状态 | 刷新后保留；后续追问整理不得覆盖 |
| 隐藏讲解 | 原题和原图仍显示，主讲解与追问讲解都隐藏 |
| 窄屏 390px | 无横向页面溢出，筛选和编辑可操作 |
| 原图缺失／归档服务出错 | 数据管理显示具体失败或未完成原因 |

## 第三关：独立持有与备份

1. 对完整笔记导出备份，记录笔记数、来源数、附件数及 SHA-256。
2. 关闭 Codex；将原始上传文件移到临时目录；断网。打开已保存的网页、题目、讲解及原图。不要删除测试原文件，验收后可移回。
   原上传文件独立性可单独运行 `npx tsx scripts/verify-original-independence.ts`：仅暂移已归档且摘要相符的 Codex clipboard 临时 PNG，读取真实服务后自动恢复；不修改业务数据，不代替关闭 Codex／断网步骤。结果 `.local/original-independence-report.json`。
3. 修改一条心得，使用此前备份恢复（网页明确提示替换当前库）；确认恢复前安全备份存在，备份时的文字、原图、标签、错题和掌握状态一致。
4. 使用缺图、被篡改、未知版本或含多余路径的备份，确认被拒绝且现有数据不变。
5. 在一个空 `SHIZHI_DATA_DIR` 的隔离实例恢复备份，核对语义记录和图片摘要一致。这验证 v1 数据可导入，不代表已完成 PostgreSQL 或在线账号迁移。

## 证据记录格式

每项保留：时间、真实操作方式、会话／轮次／笔记／附件 ID、预期、实际、图片尺寸与摘要、必要截图。当前状态见 VALIDATION.md；未测项不可写通过。
